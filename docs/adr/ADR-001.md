# ADR-001: Constraint de exclusao no banco em vez de apenas lock otimista

Status: aceita
Data: 2026-10-29

## Contexto

Reservas do mesmo recurso nao podem se sobrepor. Duas solicitacoes simultaneas para o mesmo horario devem produzir no maximo uma reserva aceita.

## Alternativas

a) Apenas checar no codigo com SELECT antes de INSERT.
b) Lock otimista com versao.
c) Constraint de exclusao no banco (EXCLUDE USING gist sobre tstzrange).

## Decisao

Opcao c, reforcada com lock pessimista na sala (ADR-004).

## Consequencias

Positivas: o proprio banco impede sobreposicao, mesmo se o codigo falhar. Vale para sala, professor e material. Teste de concorrencia comprova que apenas uma reserva entra.

Negativas: precisa extensao btree_gist habilitada. Erro do banco vira 409 na aplicacao.

## Evidencia

InicializadorBanco cria tres constraints. SobreposicaoTest e ConcorrenciaTest comprovam o bloqueio.

## Condicao de revisao

Se o banco mudar para outro que nao suporte constraint de exclusao.
